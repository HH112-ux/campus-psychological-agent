# 小程序上线部署清单（心屿 · 可执行版）

> 适用对象：`miniprogram/`（appid `wx641b560961211693`）+ `backend/`（FastAPI + MongoDB + nginx，compose prod 编排）
> 编制依据：仓库当前代码、`docs/crisis-response-sop.md`、`docs/prod-deploy-drill-2026-11-10.md`
> 状态标记：**[已就绪]** 代码/配置已有；**[需改代码]** 代码里还是占位或本地值；**[需用户提供]** 需你采购/申请；**[需校方决定]** 需校方拍板

## 一、时间轴总览（按依赖排序）

```
第 0 天 ┬─ A1 小程序主体认证 ────────────────┐
        ├─ A2 域名注册 + ICP 备案（最长）────┤
        ├─ A3 类目资质确认（可能需前置审批）──┤
        └─ A4 校方三项决定（留存/转介/SLA）───┤
                                            │
第 1–3 天 ┬─ B1 服务器采购 + Docker 环境 ───┤（可与 A 并行）
          ├─ B2 CA 证书申请 ────────────────┤
          ├─ B3 凭据申请（微信/智谱/ASR）────┤
          └─ B4 隐私政策文本定稿 ────────────┤
                                            ↓
备案通过后 ┬─ C1 代码侧收尾（apiBase 等）→ C2 后端部署与初始化 → C3 验证
                                                                  ↓
                                            D1 后台域名/隐私配置 → D2 提审 → D3 发布
                                                                  ↓
                                            E1 上线后监控/备份/日志
```

**关键依赖**：备案没过 → 域名不能用 → 小程序 `request` 合法域名填不了 → 不能提审。所以 A2 必须第一天启动。

### C2 服务器规格与加固

| 项 | 建议值 | 依据 |
|---|---|---|
| 规格 | 2 vCPU / 4 GB 内存 / 60–80 GB SSD，2 GB swap | 单机三容器（api 0.3–0.6 GB + mongo 0.5–1 GB + nginx 极小），校园级并发远小于此；留出 Mongo 索引与备份空间 |
| 系统 | Ubuntu 22.04/24.04 LTS 或 Debian 12 | 与演练环境一致（Ubuntu 24.04 + Docker 29.x） |
| Docker | Docker Engine + compose v2（`docker compose` 而非 `docker-compose`） | 编排文件用 `profiles` 与 `depends_on.condition`，旧版不支持 |
| 防火墙 | 只开 443、80；SSH 22 限制来源 IP | 与 prod 编排一致：443 唯一业务入口，80 只做跳转 |
| SSH 加固 | 禁用密码登录、禁 root 直连、改非默认端口或加白名单 | 项目含未成年人心理数据，属敏感系统 |
| 时区/时间同步 | Asia/Shanghai + chrony/ntp | 告警冷却与留存期限按时间计算 |

## 六、凭据清单（全部不入库）

| 凭据 | 来源 | 缺了会怎样 | 更换/丢失后果 | 状态 |
|---|---|---|---|---|
| `WX_APPID` / `WX_SECRET` | 微信后台 → 开发管理 → 开发设置 | prod 启动校验拦截；登录失败 `40013` | AppSecret 可在后台重置，重置后需重启 api | **[需用户提供]**（appid 已固定在代码 `wx641b560961211693`） |
| `ZHIPU_API_KEY` | 智谱开放平台 | 对话主链路不可用 | 可随时轮换 | **[需用户提供]** |
| `ASR_ENDPOINT_URL` / `ASR_API_KEY` | ASR 供应商 | 语音转写不可用（`ASR_ENABLED=true` 时启动校验要求非空） | 可轮换 | **[需用户提供]** |
| `JWT_SECRET` | 自行生成（≥32 位随机） | 启动校验拦截 | **轮换 = 全部用户被登出**，需重新登录 | **[需用户生成]** |
| `DATA_ENCRYPTION_KEY` | 自行生成（base64，32 字节） | 启动校验拦截 | **丢失 = 全部历史密文永久不可解密，无法恢复**；轮换按下方三步走（新钥 + `DATA_ENCRYPTION_KEY_ID` + 旧钥入 `DATA_ENCRYPTION_KEY_PREVIOUS`），旧密文自动兜底解密 | **[需用户生成 + 离线备份]** |
| `MONGO_ROOT_*` | 自行设定 | compose 变量替换直接报错 | 泄露 = 全库失守；需立即改密并轮转业务账号 | **[需用户生成]** |
| `ALERT_WEBHOOK_URL` | 企业微信群机器人 | 高危告警只剩日志，值班人收不到 | 可替换 | **[需校方提供群]** |

> `DATA_ENCRYPTION_KEY` 是这套系统里唯一「丢了就再也救不回来」的密钥：库里 `openid`、对话摘录、打卡备注等敏感字段都是它加密的。建议至少两处离线保管，且不要与数据库备份放在同一位置。

## 七、本次演练暴露、上线前必须固化的两件事

1. **镜像与依赖源**：演练中 Docker Hub 直连不可用，`python:3.12-slim`/`mongo:7` 需走国内镜像源并手工 `docker tag` 成 compose 里写的名字；容器内 pip 也连不上 PyPI，当时用临时 `Dockerfile ARG` 绕过（**已还原，未入库**）。
   上线前建议二选一：① 在服务器配置 Docker registry mirror + 全局 pip 源；② 在本机构建好镜像推到私有仓库，服务器只 `pull`。
2. **`SHARED_STATE_BACKEND=memory`**：演练时 prod 下只告警不拦截。上线必须换成 redis，否则进程重启后限流计数清零，告警冷却失效可能造成重复轰炸值班人。

## 十一、最小上线路径（如果时间紧）

按「不做什么就上不了线」排序，只有这 6 件是硬阻断：

1. **A2 备案通过**（最长，第一天启动）
2. **B2 CA 证书**（小程序不接受自签）
3. **C1-① `apiBase` 改成 HTTPS 域名**（否则真机必然请求失败）
