# 危机词库变更流程

危机词库是安全红线的第一道防线，任何改动都必须按本流程执行。**宁可误报，不可漏报；召回只许升，不许降。**

## 1. 变更类型

| 类型 | 说明 | 示例 |
|---|---|---|
| 新增一级词 | 强信号（自杀/轻生类直接表述） | "跳楼"的变体写法 |
| 新增二级词 | 风险语境弱信号（计分制） | "好累" |
| 级别调整 | 二级升一级、一级降二级 | — |
| 删除/收窄 | 因误报反馈收窄（如"解脱"在引用语境） | — |
| 变体扩充 | 拼音谐音、字间加符号等 | `buxianghuo`、`不 想 活` |

## 2. 变更流程（五步闭环）

1. **提交变更**：以 issue/PR 提出，写明：变更词条、理由、来源（误报反馈 / 案例 / 运营发现）。
2. **回归评估**：在危机测试集上跑回归——**召回不得下降**，并记录误报变化（新增误报必须说明处理）。
3. **评审**：至少 1 人评审；涉及删除一级词或级别调整，必须评审通过方可合入。评审关注词条歧义与上下文误伤面。
4. **上线**：词库支持配置热更新；上线后立即核对线上命中。
5. **记录审计**：变更写入 `docs/` 下的词库变更记录（或版本化词表文件），包含：日期、词条、级别、回归结果、操作人、回滚方式。

## 3. 回滚

- 每次上线保留上一版词表快照（版本化），24 小时内可一键回滚。
- 触发回滚：上线后误报激增、线上召回异常、评估集回归未通过但仍上线的（不允许，见下）。

## 4. 禁止事项

- 禁止绕过回归评估直接热更新（词库改动必须先过测试集）。
- 禁止在回归未通过的情况下上线（除非回滚方案已就绪且经评审批准）。
- 禁止删除一级词而无替代覆盖方案（强信号词宁可保留误报面）。
- 禁止把用户对话原文写入词库变更记录——记录只允许脱敏词条与统计。

## 5. 误报反馈闭环

用户点击"这不是我的本意"关闭卡片时，反馈进入调优清单（只记触发词条与频次，不记对话原文）。调优清单是词库变更的主要输入之一，每两周至少处理一次。

## 6. 审计要求

- risk_events 留存 ≥ 12 个月（开发文档约定），词库变更记录与 risk_events 配合可完整还原"何时、因何词条、触发过什么"。
- 评估集本身也纳入版本管理（`docs/eval/`），词库回归结果可复现。
