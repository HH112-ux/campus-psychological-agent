### 2.3 `_COLLISION_SUFFIX`（`cb8b891`）

**判定：未通过（新引入危机漏报）。**

实现位于 `crisis.py:69-72`、`:87-88`：

```python
_COLLISION_SUFFIX = {"不想活": "动跃躍蹦跳跑走", "寻死": "觅"}
...
if after and after[0] in _COLLISION_SUFFIX.get(phrase, ""):
    return True
```

`after` 取自 **`normalize` 之后**的文本，而 `normalize` 会删除全部标点与空白。于是「不想活」后面只要跟一个「走/跑/动」，无论中间有没有句号逗号，都会被当成「不想活动」豁免：

```text
我真的不想活，走不动了      -> none   [红线]
不想活，走路都没力气        -> none   [红线]
不想活。动不动就想哭        -> none   [红线]
不想活动，也不想活了        -> high   （第二处命中，侥幸救回）
我不想活，动都不想动        -> none
```

同时确认本轮要求保留的行为都正常：

```text
我不想活了 / 我不想活下去 / 寻死 / 寻短见 / 我不想活着了 -> high
我今天不想活动，只想躺着 / 我不想活跃 / 寻死觅活地非要辞职 -> none
```

这不是理论边界：「我真的不想活，走不动了」是自然口语，且命中词只有 L1「不想活」，一旦被豁免，整句降为 `none`，危机卡片与告警都不会触发。**属安全红线回归，阻断上线。**

修复方向：碰撞判定改在保留标点的原文上做（或要求后续两字构成「活动/活跃」且中间无标点），不要复用已 `normalize` 的字符串。

## 3. 契约一致性

### 3.1 `detect` 与 `sanitize`

**跨行口径：已统一。** `detect` 对含 `\n` 的输入直接复用 `sanitize`（`compliance.py:309-311`），23 条跨行样本两端结果一致，没有出现「检测拦、替换放」或反之。

**单行分句：仍未统一。** `detect` 在无换行时对整串 `_squash` 后判定，`sanitize` 则按 `。！？!?` 切成句子分别判定。构造只有一方命中的输入：

```text
'你是。抑郁症'    detect=diagnosis  sanitize_hits=[] -> 原样放行
'你得了。抑郁症'   detect=diagnosis  sanitize_hits=[] -> 原样放行
'你可能。是抑郁症'  detect=diagnosis  sanitize_hits=[] -> 原样放行
'你患上了！焦虑症'  detect=diagnosis  sanitize_hits=[] -> 原样放行
'你是？抑郁症'    detect=diagnosis  sanitize_hits=[] -> 原样放行
```

生产路径只调用 `sanitize`（`chat.py:275`、`:333`），`detect` 仅被测试使用，所以这首先是「测试断言与线上行为不一致」的契约问题；但 `你得了。抑郁症` 也确实能从 `sanitize` 透传，属红线兜底的一个小口子。

### 3.2 `evaluate` 的入参契约

**差异仍在，但不影响生产。** `evaluate` 仍要求已归一化文本（`crisis.py:186`），直接传原文时空格/标点会破坏否定豁免：

```text
'不 想死'   raw=high  norm=none
'没 想自杀'  raw=high  norm=none
```

生产调用只有 `detect_risk`（内部先 `normalize`）、`contains_crisis_terms` 与测试；`long_memory` 用 `contains_crisis_terms`，与 `detect_risk` 同一口径。因此当前无线上影响，属潜在 API 误用风险。
